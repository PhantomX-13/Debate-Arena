# Demo script (2-3 minutes)

Use a real decision. Do not stage one.

1. (15 s) Hook: "We compare two choices with your goals and your team's views, check the claims, then leave the decision with the people involved."
2. (20 s) In Discord, post a real request, for example the team's own: "Which hackathon idea should we build?" The Moderator asks the profile questions; answer them.
3. (50 s) Show the two options, the Moderator inviting optional teammate views before debate, the attributed contributions, Advocate A and B, Coach readiness, and Fact-Checker results. Make clear that a view is an opinion until its factual claims are checked.
4. Show the same Learning question for a beginner and an experienced persona only after both runs are verified. Explain any difference using the Learning verdicts (`PROCEED`, `SKIP_FOR_NOW`, `LEARN_THEN_PROCEED`, `NOT_NOW`). Different verdicts do not prove accuracy.
5. (20 s) Judge gives a short, plain-language recommendation followed by the detailed review. Humans vote; show the report path and explain that the vote is the decision.
6. (10 s) Close: "Honest, not hostile. Supportive, not flattering."

Show the MORE INFO follow-up only if the live evidence pass has completed. A live A/B outcome is recorded in `DA-7F07-L5`; the live `PENDING` outcome is recorded in `DA-7F07-L6`. If demonstrating the new group-input feature, be clear that the verified Project case had no teammate contributions; do not stage contributions as if they were real. The HTML previews are scripted examples.

If no fake source happens to appear live, show the verify_sources.py test with a planted bad link and label it clearly as a test.
Keep a clearly labeled recording as backup. Live timing varies and provider limits have interrupted a case; rehearse before presenting.
